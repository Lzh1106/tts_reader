## 一、这一版解决了什么

**用户原话**：「接到类似微信之类又响铃的消息时，不打断朗读……老是打断重新开始读这句话太影响使用体验」，
以及「视频响了后延迟几秒才停」。

| 场景 | 现在的行为 |
| --- | --- |
| 微信等消息提示音 | 朗读**完全不中断** —— 不停顿、不重读那一句 |
| 播放视频 / 来电 | **立刻**让位暂停（不再有延迟）；结束后不自动接回 |
| 用户手动恢复播放 | 正常恢复，且**下一次视频仍然会让位** |

## 二、核心设计：按「焦点类型」分流（**这是本版最重要的知识**）

### 2.1 为什么不能靠"暂停再接着读"

**Android TTS 没有"从半句续读"的能力**（`TextToSpeech` 只有 speak/stop，没有 seek）。
只要暂停过，恢复时**只能把这一句从头重发** —— 用户听感就是"老被打断、同一句反复读"。
**所以想不重读，就根本不能暂停。**

### 2.2 判据是"类型"，不是"时长"

排查经过了两版，最终定在类型上。**结论与依据都要记住，否则会重走弯路**：

真机日志（2026-10-15 00:10 / 00:25）给出的决定性差异：

```
微信通知 → 音频打断[收到] type=pause    然后 1.1 秒后 type=pause begin=false
播放视频 → 音频打断[收到] type=unknown  然后**永远没有** begin=false
```

与 `audio_session 0.1.25` 源码逐条对上（`lib/src/core.dart:254-283`，`onAudioFocusChanged` 回调）：

| Android 焦点码 | 折叠成 | 会不会有"结束"事件 |
| --- | --- | --- |
| `lossTransient`(-2) / `lossTransientCanDuck`(-3) | `pause` / `duck` | **会**（瞬时） |
| `loss`(-1)（**永久**失去焦点） | **`unknown`** | **不会** |

**关键事实**：`unknown` 在 Android 上**只有 `loss` 这一个来源**
（`core.dart` 里另两处 `unknown` 在 iOS 分支，第 70/79 行）。

**"视频为什么没有结束事件"也由此解释**：原生在收到 `AUDIOFOCUS_LOSS` 时会
`abandonAudioFocus()`（`audio_session` 的 `AndroidAudioManager.java:307`）——
我们不再持有焦点，系统自然不会再通知我们"对方结束了"。

### 2.3 实现位置

* **判定与分流**：`lib/tts/media_interruption.dart` → `_onInterruption()`
  ```dart
  final bool permanent = event.type == AudioInterruptionType.unknown;
  if (permanent) { _pausedForItNow(); return; }   // 视频/来电 → 立刻让位
  // 其余（pause / duck）→ 不暂停，朗读继续
  ```
* **"已让位"标志的清理**（见第四节，这是本版修的一个真 bug）：
  * `MediaInterruptionController.notifyUserResumed()` 里清 `_pausedForInterruption`
  * `TtsAudioHandler._pushState()` 里 `if (playing) notifyUserResumed()`

### 2.4 如果将来这个判据失效了怎么查

看日志里 `type=` 那一栏即可复核（`音频打断[收到] type=… begin=…`）。
若换 ROM / 升级 `audio_session` 导致映射变化，这一栏会立刻体现出来 ——
**不要凭猜改判据，先看真机日志的类型**。

### 2.5 明确**没有**改的东西（避免后人误判）

* **没有**改 `androidWillPauseWhenDucked`（仍是 `true`）。
  v1.21.38 曾改成 `false` 想让提示音不打断，结果真机「被视频打断失效、通知栏图标也错」，
  v1.21.39 已回退。**本版用的是类型分流，不动这个开关**。
* **没有**改焦点申请/释放策略（暂停仍不释放焦点，只有 stop / 会话结束才释放）。

## 三、排查过程（供后人复用方法）

1. **先加观测，再改代码**：打断这条链原本**一条日志都没有**，
   于是"被通知打断后不读了"到底是①没收到事件②收到了没接回③接了但引擎不响应，完全无从判断。
   加了 `音频打断[收到/开始/让位/结束]` 与 `打断暂停[进入/完成]`、`打断接回[完成]` 之后，
   问题一次就定位了。
2. **第一版（v1.21.50）用"宽限期 2 秒"**：短的是通知、长的是视频。
   它解决了"通知打断"，但**视频要等满 2 秒才让位**（用户实测反馈"延迟几秒"）。
3. **第二版（v1.21.51→52）改用类型分流**：用户反馈的"延迟"反而促成了更干净的修法。
4. **教训**：`type=unknown` 这个线索一直在日志里，只是前两版没去核对源码映射。

## 四、本版顺带修掉的真 bug（真机日志暴露）

**现象**：看完视频手动恢复朗读后，**下一次视频不再让位**。

**日志原文**（2026-10-15 00:25）：
```
00:25:39  视频 → 让位暂停（pausedForIt=true）
00:25:55  用户手动点播放恢复            ← 此处"已让位"标志没被清
00:26:30  通知来了 → "已经让位暂停过了 → 不重复处理"（用的还是旧标志）
```
那一次侥幸没出事（中间那条通知的结束事件顺手清了它），但标志**粘住**是实打实的隐患。

**修法**：把清理放在 `TtsAudioHandler._pushState()` 里（**所有来源唯一的公共出口** ——
TtsManager 与 PDF 会话、应用内点播放、通知栏点播放，最终都走这里），
并在 `notifyUserResumed()` 里一并清。**只清 `TtsManager._restart` 会漏掉 PDF 那条路。**

## 六、环境与工具（踩过的坑，务必照做）

### 6.1 构建

```powershell
Set-Location 'D:\dsh\tts_reader'
. 'D:\ttsbuild\env.ps1'          # 必须！否则 Gradle 会去联网重下 gradle-8.4 而失败
flutter clean
flutter build apk --release
```

* **`pwsh` 不在 PATH**，只有 PowerShell 5.1 → 用 `& .\tool\xxx.ps1`（call 操作符），不要用 `pwsh -File`。
* **`git` 不可用**（不在 PATH）→ 提交走 GitHub REST API，见下。

### 6.2 提交到 GitHub（本机特有的坑）

本机装着 **`steamcommunity_302.cli`**（GitHub 加速工具），它监听本机 443 并用**自签 CA**
劫持 GitHub 流量。于是：

* **PowerShell 能通**（走 Windows 证书库）
* **Node 的 `fetch` 会失败**：`TypeError: fetch failed` / 原因 `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`

**正确做法**：把它的根 CA 喂给 Node（`NODE_EXTRA_CA_CERTS`），**不要**关掉证书校验。

**现在这一步已经自动化，不需要手动做**：

1. `tool/export_local_ca.ps1` 会把本机加速工具的根 CA 导出成
   `build\local-ca.pem`（**不进仓库**，`build/` 已在 .gitignore）。
   ```powershell
   & .\tool\export_local_ca.ps1
   ```
2. `tool/gh_sync_release.js` 启动时若发现该文件存在、而环境变量还没设，
   会**带着它重新执行自己**（TLS 信任锚只能在进程启动时确定，运行期改不了）。

所以正常情况下直接跑就行：

```powershell
$node = 'C:\Users\user\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
& $node tool\gh_sync_release.js 'D:\dsh\tts_reader-publish' '<提交信息>' 'vX.Y.Z'
```

**若仍失败**：加速工具更新后 CA 会轮换 → 重新跑一次 `export_local_ca.ps1` 即可。

Token 在 `C:\Users\user\.dsh\dsh_wechat\logs\gh-token.txt`（只在本机，不进仓库）。

### 6.2.1 ⚠️ 写 `.ps1` 必须带 UTF-8 BOM（PowerShell 5.1 的坑）

本机只有 **PowerShell 5.1**，它读无 BOM 的 `.ps1` 会**按 ANSI（GBK）解码** ——
文件里的中文会变成乱码（`·` → `路`），甚至**直接把字符串语法搞坏、脚本无法运行**。

**规矩**：含非 ASCII 内容的 `.ps1` 一律存成 **UTF-8 with BOM**。
（纯 ASCII 的可以不带；仓库里 `verify_apk_lame.ps1` / `snapshot_source.ps1` 都带 BOM。）

补 BOM 的做法（不会改内容）：
```powershell
$p = 'D:\dsh\tts_reader\tool\某脚本.ps1'
$txt = [System.IO.File]::ReadAllText($p, (New-Object System.Text.UTF8Encoding($false)))
[System.IO.File]::WriteAllText($p, $txt, (New-Object System.Text.UTF8Encoding($true)))
```

### 6.3 发布白名单（**别只写子目录**）

`tool/gh_sync_release.js` 的发布树由脚本按白名单复制而成：
目录 `lib test integration_test tool android` + 文件
`analysis_options.yaml CHANGELOG.md LICENSE pubspec.yaml pubspec.lock README.md`。

⚠️ **第一次同步时曾把白名单写成 `android/app/src`**，结果把
`android/{build.gradle,settings.gradle,gradle.properties,gradlew,gradlew.bat}`
从仓库里**删掉了**（等于 clone 下来编不了）。**必须写整棵 `android/`**，
排除项交给脚本里的 `skip` 正则与 `.gitignore`。

### 6.4 绝对不要用 PowerShell 回写文本文件

我曾用 `Set-Content -NoNewline` 改 `pubspec.yaml` 的版本号，
**把 64 行的文件压成了一行**（换行全被吃掉）。改 `.dart` / `.yaml` 一律用编辑器工具
（`read` + `edit`），或用 `Copy-Item` 做字节级还原。

## 七、我在这次任务中犯的错（如实记录，供后人避坑）

1. **改分句规则却没涨解析缓存版本** → 真机表现为「朗读游标来回跳、反复重启、卡住」。
   现场日志里的 `index=926/19949` 是决定性证据（19949 是旧分句规则的句数，新规则是 15799）。
   修法：`DocumentService.parseRevision` 2 → 3。
   **规矩：任何影响解析结果的改动，必须同时 +1 这个版本号。**
2. **同步仓库时误删 android 构建脚本**（白名单写窄，见 6.3）。
3. **两次归因错误**：先把崩溃赖成"重入"，又赖成"EPUB 页"，害用户白跑一次实验。
   **教训：日志相邻性 ≠ 因果。** 崩溃日志是串行队列 + 延迟落盘，"断在哪"只说明写到哪。
4. **一次改错判据差点蒙混过关**：我改了 `TtsManager.resume()` 的闸门并自认为修好了，
   **负向自检没红**，才发现那个判据根本不会触发（`pause()` 并不清 `_speaking`），随即回退。
   **教训：负向自检不是形式，它是唯一能证明"用例真的在守这条线"的手段。**
5. **CHANGELOG 里写了没做过的改动**，自查时发现并删除。
   **教训：变更日志只能写真的改了的东西。**
6. **用 PowerShell 写 `.ps1` 踩了编码坑**：新脚本含中文但没 BOM，PowerShell 5.1
   按 GBK 解码后直接语法错误、跑不起来（见 6.2.1）。
   **教训：本机写 `.ps1` 一律带 UTF-8 BOM。**

## 八、未决事项 / 已知限制

1. **视频结束后不自动恢复朗读**：当前设计如此（视频还在响却突然冒出朗读更糟）。
   若要"视频结束后自动接着读"，需要另做——注意 `loss` 之后我们**不会**再收到结束事件，
   得靠重新申请焦点来探测。
2. **推荐签名证书仍未启用**（`D:\Workspaces\default-workspace\keys\tts_reader-release.jks`）：
   一启用签名就变，必须卸载重装（**书库条目 / 设置 / 阅读进度会清空**）。独立动作，等下令。
3. **全量测试偶发 1 条红**：Windows 临时目录删除被占用（`PathAccessException`，
   "after the test had completed"）。**不是断言失败**，涉事文件单跑全过。
4. **"不打断"的代价**：通知响的那一两秒，朗读**不会自动压低音量**（试验证过：
   `flutter_tts` 的 `setVolume` 只对**下一句**生效，正在读的这一句压不下去）。
   当前的取舍是"宁可混着响，也不打断"。
5. **已知的历史遗留**：`StorageService.removeDocument` 删库条目时不清 `covers/<id>.jpg`（孤儿文件）。
   封面功能已于 1.21.46 整条撤回，此项暂无影响。
