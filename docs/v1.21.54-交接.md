## 五、未决事项二：PDF 目录朗读位置图标失效

### 现状（代码层面已核对）
PDF 原版式目录在 `features/pdf_reading/pdf_reading_page.dart` 的 `_openToc()` 里，
**已经**用了和文字档同一个组件 `TocCurrentItem`（图标是 `TocCurrentItem.currentIcon` = `graphic_eq`），
判据是 `pageIndex == currentPage`，而 `currentPage = _session.current?.pageIndex ?? 0`。

### 已定位的具体缺口（**这是代码事实，不是推测**）
`_openToc()` 在 **打开面板那一刻**把 `currentPage` 取成一个局部变量；
面板是 `showModalBottomSheet` 的独立路由，**不订阅 `_session`**。
所以：面板开着期间朗读推进，那一行「当前」标识**不会跟着动**。

### 尚未解释的部分（用户报的是「失效」，可能不止上面这一条）
- 是否「打开时就没标在正确页」——未验证，需要真机/日志。
- 是否与「重进阅读页后 `_session.current` 未就绪」有关——未验证。

1. 把面板内容包进 `ListenableBuilder(listenable: _session)`，让当前页**随会话实时更新**。

- **没有**加观测、**没有**复现、**没有**改代码

### 代码结构上的关键事实（这些是核对过的，可继续用）

**A. 两个入口其实不是同一条路**

| 入口 | 实际调用 | 选谁 |
| --- | --- | --- |
| 通知栏 / 耳机 | `TtsAudioHandler.play()` → `_source.playFromCursor()` | 走**当前媒体来源**（`_source`） |
| 文档库底部控制条 | `ReadingControlBar._pickSource()` 自己判 → 直接调 `pdf.resume()` 或 `tts.playFromCursor()` | **PDF 优先**（`pdf.isPlaybackActive`），否则 TTS |

所以「两入口同源」这个假设**不成立**；但它们都能导致症状，
要么是**当前来源指错**，要么是**会话自身的位置/暂停态错**。

**B. 换书时确实会清掉 TTS 侧归属**
`TtsManager.loadDocument(B)` → `terminateForDocumentSwitch(nextDocumentId: B)`
→ 清 `_doc`、`_speaking/_paused`、`_pendingCursor`，并 `releaseFocus()`；
若 PDF 曾占着通知栏，还会 `audioHandler?.activate(this)`。
同 id 重进不打断（§4.60 守卫，有用例守着）。

**C. `PdfReadSession.open(B)` 同样会终止 TXT 侧**
传 `nextDocumentId` 给 `TtsManager.terminateForDocumentSwitch`，并 `_current = null`、清 playing/paused。

**D. 唯一明显的「位置可能被旧值带走」的口子在 `_rebindIfCleared()`**
`playFromCursor()` / `resume()` 都会先 `_rebindIfCleared()`：
当 `_doc == null` 时用 `_lastDoc / _lastDocId` **自动绑回**。
而 `_lastDoc` 是「最近一次 loadDocument 的文档」——
**如果 B 的解析还没完成（还没 `loadDocument`），此时按播放会把 A 绑回来并读 A。**
这是当前最值得先验证的假设（**未验证**）。

### 下一步建议（未执行）
1. 先加观测（**不要直接改行为**）：
   - 记录进入 B 阅读页的时机 vs `TtsManager.loadDocument(B)` 的时机；
   - 记录 `playFromCursor()` 进来时的 `_doc / _lastDoc / _documentId / speaking / paused / 当前 source`；
   - 两个入口各打一条带入口名的日志，便于区分。
2. 复现序列必须严格按用户说的走：

3. 按上面 D 的假设先做最小验证用例（暂停 A → 不加载 B 就调 `playFromCursor()` 看读谁），
   如果成立，修法应落在「换书时把 `_lastDoc` 一并失效 / 播放前校验当前阅读页文档」，
   **而不是**在按钮层加判断。
4. 用例要覆盖：EPUB、PDF 各一；两入口各一；旧会话切书后失活；单本书暂停/恢复不回归。

### 六之补：2026-10-16 第二轮排查结果（**6 个假设全部被否**）

用户确认的复现入口是**①文档库点书卡片**，且「B 已加载出正文、两个入口都会、与位置无关」。

按这条路径逐条实测（都在 `test/reader_cross_document_session_test.dart`）：

| # | 假设 | 实测结果 |
| --- | --- | --- |
| 1 | `playFromCursor()` 经 `_rebindIfCleared()` 绑回 A | ❌ **否**：`playFromCursor()` 里没有该调用 |
| 2 | 切书后还能走 `resume()` 恢复 A | ❌ **否**：切书把 `_speaking` 置 false，`resume()` 进不去 |
| 3 | 暂停中的 PDF 会话抢占派发 | ❌ **否**：切书时已 `isPlaybackActive=false` |
| 4 | 通知栏 `_source` 仍指向旧 PDF | ❌ **否**：实测已切到 `tts-manager` |
| 5 | 页面入口不校验文档，被旧书吃掉 | ❌ **否**：点 B 章标题后 `holdsB=true` |
| 6 | 真实压栈两页：A 暂停 → 开 B → 点播放 | ❌ **否**：`holdsA=false holdsB=true title=B` |
| 7 | 解析窗口期（B 未加载完）点播放 | ❌ **否**：`holdsA=false`，`_doc==null` 时什么都不做 |

**其中一条曾经"变红"是假象**（必须记下来，避免后人误判）：
第一次用 `pumpWidget` 换掉整棵树来测，A 页被 dispose → 出现 `holdsA=true`。
换成**真实 navigator 压栈**（A 页仍在栈里）后立刻变绿。
**结论：测换书必须用 push 压栈，不能用 pumpWidget 顶部替换。**

**当前判断**：在纯 Dart 层，切书后 A 已经完全脱离，两个入口都读不到它。
剩下唯一没排除的差异是**真机侧**（解析真实耗时、MediaSession/音频焦点被系统抢占）——
这些单测覆盖不到，只能靠真机日志。为此已给 `TtsAudioHandler.play()` 与
文档库控制栏的两个播放分支加了带全字段的诊断日志（见 v1.21.54-test 包）。

**下一步（等日志）**：拿 `媒体控制[play source=... title=... pdfKey=...]` 这几行，
看播放那一刻 `source` 与 `title` 是谁，即可判定是"派发错"还是"真机层另有原因"。
